## COMPONENT BREAKDOWN

### 1. SESSION MANAGER

**Responsibility:** Session lifecycle, state persistence, interruption recovery, **authentication flow**

**Inputs:** User request, CLI args, checkpoint data, browser callback

**Outputs:** Session state, restored history, interrupt handlers, authenticated token

**Lifecycle:**
- `createSession()` - Initialize session with config
- `checkpoint()` - Save state on interrupt/SIGTERM
- `restore()` - Load checkpoint on `--resume`
- `cleanup()` - Delete checkpoint on success
- `loginWithBrowser()` - NEW: Initiates browser-based OAuth flow
- `exchangeCodeForToken()` - NEW: Handles callback token extraction

**Authentication Flow (IMPLEMENTED):**
```
1. No token provided → browserLogin()
2. Open https://mela.aii.et/signin in browser
3. User completes login/registration in browser
4. User copies token from localStorage (key: "access_token")
5. User pastes token in terminal
6. Save token to .env, continue to agent
```

**Failure Modes:**
- Checkpoint corruption → fallback to fresh session
- Stale checkpoint (>24h) → warn user
- Missing permissions on checkpoint file → log error, continue
- Login timeout (5 min) → exit with error
- Token extraction failure → retry or manual entry

### Implemented Flow

```
1. No token → browserLogin() opens https://mela.aii.et/signin
2. User logs in, copies token from browser localStorage
3. User pastes token in terminal
4. Token saved to .env, agent starts
5. Invalid token → automatic re-auth prompt
```

### CLI Commands
- `mela-coder --login` - Force browser login
- `mela-coder --refresh-token` - Attempt token refresh
- `/login` in REPL - Login within session

## SECURITY CONSIDERATIONS

1. **Token storage**: Store in `.env` (automatically gitignored), not in code
2. **Timeout enforcement**: 5-minute timeout on login to prevent hanging
3. **Clean handling**: Always close readline interface after token receipt

## IMPLEMENTED FLOW

- Browser opens to signin page
- User manually copies token from localStorage after login
- User pastes token in terminal
- Token saved to `.env` and used for API calls

---

## KEY DESIGN PRINCIPLES

1. **LLM is NOT the agent** - Only planner/reasoner
2. **Runtime-driven** - State machine controls execution
3. **Verification-first** - Always verify after changes
4. **Recovery-aware** - Checkpoints, rollbacks, retries
5. **Modular by design** - Skills, tools, memory as plugins
6. **Context-efficient** - Token budgeting, summarization
7. **Seamless auth** - Browser login flow for better UX
