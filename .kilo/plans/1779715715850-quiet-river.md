# Fix: Model outputting file/shell content as text instead of tool calls

## Problem Analysis

When the model generates files or runs commands, it outputs them as plain text instead of proper tool call format:

**Current (broken):**
```
one.html
<!DOCTYPE html>
...
```

**Expected (working):**
````markdown
```write_file
one.html
<!DOCTYPE html>
...
```
````

Similarly for shell commands:
**Current:** `python3 -m http.server 8000` (displayed as text)
**Expected:** ````execute_bash` with the command

## Root Causes (Detailed)

1. **`filterToolAndFileFence` in `loop.ts` (lines 86-99)**: 
   - Detects raw file content patterns like `one.html\n<!DOCTYPE html>` 
   - Sets `insideFileContent.value = true` and returns early, stripping the content from display
   - Purpose: prevent raw file content from being shown to user
   - PROBLEM: The raw content is stripped but NOT converted to a tool call

2. **`parseMelaResponse` in `parser.ts` (lines 102-167)**:
   - Only parses properly formatted fenced tool blocks: ```tool_name\ncontent```
   - Does NOT detect raw file content patterns (filename.ext followed by code)
   - Returns text only when no tool call is found, causing file content to be displayed

3. **`extractCodeBlock` in `loop.ts` (lines 241-265)**:
   - Has TWO detection methods:
     - Fenced code blocks: ```javascript\ncode``` - USED by auto-save fallback (line 544)
     - Non-fenced format: filename.ext\n<content> - NOT working properly
   - `FILE_HEADER_RE` pattern (line 239) expects: `filename.ext\n<content>` at start of text
   - `isFileCreationTask` (line 219) checks: `/create|generate|make|write|build|produce|save|output/i` AND has `.ext` pattern

4. **The Critical Issue**:
   - Model outputs: `one.html\n<!DOCTYPE html>\n...` (raw format)
   - `filterToolAndFileFence` detects this and strips it (sets insideFileContent=true)
   - `parseMelaResponse` sees no fenced tool call, returns text with the content
   - `extractCodeBlock` expects `FILE_HEADER_RE` at the START of text, but content is in middle
   - Auto-save doesn't trigger because `extractCodeBlock(parsed.text)` returns null

## Solution Approach

### Fix 1: Enhance `filterToolAndFileFence` to NOT strip raw file content
- Remove the logic that strips raw file content (lines 86-99)
- Let the raw content pass through so `extractCodeBlock` can process it

### Fix 2: Improve `extractCodeBlock` to handle inline file content
- The current `FILE_HEADER_RE` expects start-of-text match (`^` anchor)
- Need to make it work anywhere in the text using a global search
- Extract content between filename and next tool call/end of text

### Fix 3: Detect shell commands in raw text
- Add pattern detection for shell commands like `python3 -m http.server 8000`
- Convert these to `execute_bash` tool calls when task implies execution

### Fix 4: Update system prompt examples
- Make tool call format even more explicit with more examples
